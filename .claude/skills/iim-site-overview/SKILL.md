# Indie Music India site — overview

This repo (`/Users/sibyjohn/music-india-dashboard`, remote `github.com/sibyjohn0/india-music-dashboard`) hosts **two separate products**:

1. **India Indie Music Radar** — the single-page dashboard (`index.html`, `app.js`, `style.css`, `data/*`). Documented in the root `CLAUDE.md`. Use the `debug-pipeline` skill for that half.
2. **indiemusicindia.com** — a full multi-page consultancy/content site (`CNAME` file points here). This skill and its siblings (`iim-feature-artist`, `iim-seo-check`, `iim-guide-qc`, `iim-mobile-qc`, `iim-deploy-verify`) cover this half, which has no root CLAUDE.md coverage at all.

Both halves share the same git history and deploy together via GitHub Pages on push to `main`.

## Shared nav (`assets/nav.js`)

One shared component, injected via `<script src="/assets/nav.js" defer>` on every page. Builds a grouped Discover/Tools dropdown from the `NAV` array at the top of the file, and a separate `activeFor()` path-matching array for nav-highlight state — **both must be kept in sync** when adding a new top-level page.

Every page also ships a **static fallback** `<nav class="js-primnav">...</nav>` in raw HTML, present before JS runs (and all a non-JS crawler ever sees). This is hand-written per hand-authored page, or baked into each generator's own `NAV` string constant — **it is not automatically kept in sync with `assets/nav.js`**. On 2026-10-12 we found the static fallback had zero link to `/artists/` across all ~140 pages on the site (while the JS-injected nav had it all along) — this was a real, sitewide internal-linking gap invisible to a `grep --include="*.html"` search since it only lived in `.js`. When auditing internal links, always check BOTH the JS array and the static per-page/per-generator fallback markup, and grep across `*.js` too, not just `*.html`.

## Shared theme (`assets/poppy.css`)

Bright candy-gradient theme (Bricolage Grotesque + Inter + Space Mono), rolled out mid-life of the site. Some older pages carry **dead pre-poppy dark-theme CSS** (`--bg:#0d0d0f` etc.) alongside the poppy stylesheet load — harmless if poppy.css overrides cleanly, but worth checking on any page you touch. `artists/index.html` had this until fixed 2026-10-12; `playbook/` was flagged (not yet confirmed fixed) as having actually broken legibility from this, not just dead CSS — see `iim-mobile-qc`.

## Standing content rules (apply to every edit on this site)

- **Zero em dashes, anywhere.** After any edit: `grep -c $'\xe2\x80\x94\|\xe2\x80\x93' <file>` must print `0`. Rewrite with a comma or colon.
- **Validate JSON-LD after editing any `<script type="application/ld+json">` block:**
  ```bash
  python3 -c "import re,json; [json.loads(s) for s in re.findall(r'<script type=\"application/ld\+json\">(.*?)</script>', open('PATH').read(), re.S)]; print('ok')"
  ```
- **Never invent facts.** No fabricated bios, numbers, fees, or video citations. Verify via WebSearch/WebFetch, the site's own `data/*.json`, or `mcp__youtube-data__getVideoDetails` before publishing anything as fact.
- **Update freshness markers** when content substantively changes: the `dateModified` field in the page's Article JSON-LD, and the visible "Last updated"/"Reviewed" date text, to today.
- Links in any outbound email must be clean/direct — never Gmail's `google.com/url?q=...` redirect wrapper, it reads as a scam.

## Git workflow (important — this repo auto-commits daily and may have parallel agents working on it)

```bash
git add <specific files, never -A blindly>
git commit -m "..."
git fetch origin main
git rebase origin/main   # resolve conflicts; for GENERATED files, re-run the generator fresh rather than hand-merging diffs
git push origin main
# if push is rejected: fetch + rebase again, then retry push. Never force-push.
```

## Common mistakes (do / don't)

- **Don't** grep only `--include="*.html"` to check if a page is internally linked. **Do** also grep `--include="*.js"` — `assets/nav.js` injects links client-side that never appear in any page's raw HTML source. A 2026-10-12 investigation wrongly concluded `/artists/` had zero internal links sitewide for exactly this reason; it was in the nav all along.
- **Don't** edit a generated page's output HTML (`venues/*`, `guides/*`, `live/index.html`, `news/index.html`, `toolkit/*`) expecting the fix to last. **Do** fix the generator script and re-run it — the next pipeline run (daily for venues/live/news) silently overwrites direct HTML edits.
- **Don't** run `git add -A` reflexively. **Do** add specific files you actually intended to touch — this repo has multiple agents/sessions working in it at once, and a blind `-A` can sweep up someone else's in-progress, uncommitted work.
- **Don't** assume `git rebase origin/main` will just work if another agent is actively editing files in the same working directory — it will fail with "you have unstaged changes" if their edits (or your own) are uncommitted at that moment. **Do** use `git rebase --autostash origin/main`, which stashes whatever's dirty, rebases, then reapplies it automatically — validated in practice 2026-10-12 with multiple parallel agents editing the same working tree. Plain wait-and-retry also works but autostash is cleaner and doesn't require guessing how long to wait.
- **Don't** force-push or skip hooks to resolve a push rejection. **Do** fetch, rebase again, and retry — this is the expected, safe pattern when several agents are pushing to `main` around the same time.
- **Don't** use `ScheduleWakeup` expecting it to pause/block execution — it schedules a future re-invocation, it does not wait. **Do** use a backgrounded blocking Bash loop (`while kill -0 $PID ...; do sleep N; done`) when you actually need to wait for a specific process to finish.
